# 工作区与任务业务逻辑 Demo

本 Demo 根据 `docs/workspace-task-confirmed-design.md` 制作，保留现有左侧导航、任务提醒、工作区卡片、工作区助手，以及任务详情的对话与步骤布局。仅供业务流程评审，不是正式实现或发布验收。

## 打开方式

在项目根目录启动独立静态服务：

```sh
.venv/bin/python -m http.server 5175 --bind 127.0.0.1 --directory prototypes/workspace-task-demo
```

访问 <http://127.0.0.1:5175/>。不需要正式后端；刷新页面恢复初始场景。数据只在浏览器内存，不读取或写入正式技能、任务、模型配置。

## 建议验证顺序

1. **我的工作区**：查看原有卡片结构和未关闭任务计数。HIS、CIS 被实际未关闭任务锁定；LIS 可编辑和停用。可以在 LIS 创建只有周期父计划、尚无执行的任务，检查父计划本身不锁定维护。
2. **新任务**：选择一个技能或一个工作流；选择独立／关联、非周期／周期、人工／自动。下一步预览后才创建。周期支持每天、每周多选、工作日、每月日期或月末。每月缺日可以选择跳过或月末。
3. **统一资料处理**：打开“住院结算 · 资料待补齐”，启动后进入待确认。必需资料未补齐不能继续；可选原型未提供时，统一确认仅分析文字及其影响。自动继续也不能绕过资料检查。
4. **正常执行与暂停**：任务详情右侧“演示操作”模拟步骤成功或失败。人工确认模式下，确认当前结果才进入下一步；自动继续模式自动推进。执行中提交暂停请求，当前步骤结束、必要确认完成后暂停后续步骤。
5. **完成和关闭**：步骤全部通过后为已完成，仍锁定配置；关闭需要填写原因。失败后放弃并关闭不等于业务完成，不能放行依赖后置。执行中的步骤不能强制关闭。
6. **关联关系**：初始 CIS 场景为 A → B、C → D。A 完成后 B、C 可以并行；D 等待 B、C 完成。新建关联任务可以手动选择已有前置，组成串行、并行或混合关系。不会自动交换成员产物。
7. **重跑**：从已运行的当前或更早步骤开始。默认勾选保留上次结果，生成版本号和分钟时间戳；取消只清理本次受影响范围。保留前序与独立分支，保留执行日志。受影响成员正在运行或已关闭时先阻止，不先清理结果。
8. **周期执行**：“演示控制”初始从 08:50 推进 10 分钟，触发 09:00 周期。上一周期存在未关闭子任务时再次触发会跳过；不积压、不补跑。每周期产物独立归属。暂停默认仅暂停后续周期，也可明确请求当前执行安全暂停；到期不会自动关闭现有子任务。
9. **错过预约与恢复**：打开初始“已错过预约”场景，人工选择立即执行、重新预约或关闭。“演示控制”可模拟离线或重启不确定恢复，要求人工核实，不自动重放不确定步骤。
10. **提醒与 Chat**：顶部集中处理需人工介入事项；普通进度与跳过周期留在记录。Chat 的文字先作为对话，明确确认后才登记为任务资料，执行中不替换当前输入。

## 演示边界与正式实施待办

- 模型、技能执行、目录、文件读取证据及文件产出均为明确标注的演示；没有实际模型请求、后台调度、磁盘备份或重启恢复。
- 三个技能名称与工作流仅作为独立原型场景，不与正式技能库互通。
- 资料选择当前用勾选模拟；正式文件选择、知识来源读取、共享资料绑定及同用途资源优先级待后续前后端实现。
- 对话与执行模型当前展示配置说明，实际模型下拉选择、默认设置解析、失效与备份链校验仍需正式接入，不将模型目录发现当作可执行能力证明。
- 示例结果可下载成 Markdown；“保留旧结果”仅验证列表归属和命名，正式目录安全、保存失败处理和覆盖保护仍待实现。
- 条件触发、工作流更换、复杂自动配置修复不纳入本次 Demo。
- 浏览器关闭不会继续执行；本机托盘、后台运行与恢复是正式客户端待实现能力。

## 技能与工作流串联补充

- 左侧“技能中心”列出三个演示用已发布技能，可直接用于单技能任务，或进入工作流配置。
- 左侧“工作流”支持新建、复制、编辑、增删步骤及调整顺序；每一步选择一个技能，并显式勾选任务共享输入或任意前序步骤输出。调整顺序／移除步骤后来源恢复为任务输入，要求重新核对，不静默绑定到错误步骤。
- 保存草稿不进入任务候选；检查并发布后，新任务可以选择。未关闭任务引用的工作流禁止修改，可创建副本。任务保存自己的步骤与来源快照。
- 每个实际任务／周期子任务自动生成唯一 `TASK-xxxx` 编号，重跑沿用编号；详情显示测试用例编号示例 `TASK-xxxx-TC-001`。Demo 刷新重置计数，不代表正式持久编号已实现。
- 工作区表单改用“工作区简称”，最多四位大写字母或数字，至少一个大写字母，不允许符号、纯数字或重复简称。简称可编辑，内部身份不随简称改变，历史任务仍能定位原工作区。

## 工作流设计优先评审（最新规则）

本 Demo 默认打开“我的工作流”，任务和工作区原有场景仍在侧栏中保留，待工作流确认后继续完善。工作流采用与技能库相同的标题、搜索／状态筛选和卡片结构。

1. 当前角色默认为测试工程师。技能选择只显示测试工程师技能与通用技能；可通过“演示切换角色”验证其他角色隔离。技能名称与角色均为原型夹具，不读取正式库。
2. “新建工作流”中填写名称、描述，逐步选择已创建技能并排序，显式选择任务资料或前序结果；不会自动判断业务衔接。
3. “保存草稿”与“检查并保存”均默认停用。保存成功不等于启用；卡片中明确提示任务不可选。
4. 点击“启用”会检查步骤、技能可见性及输入来源，检查通过才进入任务候选。启用后不可编辑，先停用；有未关闭任务引用时不能修改或停用，可创建副本。
5. 初始“测试分析与用例设计”可直接编辑，“需求分析与测试设计”保留此前任务引用场景以演示保护。
6. 工作流专项检查：`node prototypes/workspace-task-demo/verify-workflow.cjs`。原有 `verify.cjs` 主动启用历史场景工作流后回归任务规则，不更改默认停用原则。

以上“保存默认停用、明确启用后任务可选”覆盖本文此前“发布即进入任务候选”的原型说明。正式工作流、角色权限、模型覆盖及资料绑定尚未接通，不能据此认定正式功能完成。

## 紧凑工作流 Demo（参考附件布局）

参考用户提供的《工作流演示.html》的横向步骤链与单行编排布局，沿用现有森林绿配色、侧栏及组件风格；附件仅作为设计参考，不执行或照搬附件脚本。

- 工作流首页：紧凑横向卡片，步骤链直接可见；移除重复路径与任务“待处理”入口。
- 新建／编辑：采用独立页面，名称、描述、特殊输入要求和默认步骤确认方式集中放置。每步一行选择技能、模型、确认方式并调整顺序，输入／输出补充按需展开。
- “使用上一步结果”与其他前序结果均为叠加输入；任务资料继续保留。不填写特殊要求时采用技能原有输入输出，不修改技能包。
- 四种展示状态：草稿、待启用、已启用、已停用；检查并保存后仍需明确启用。检查配置完整性，不声称验证业务效果。
- 模型使用明确标注的演示选项；步骤可沿用技能模型或选择演示模型，确认方式可沿用工作流默认或单步覆盖。真实模型库待正式实施接入。
- 自定义工作流删除：已启用或有未关闭任务引用时阻止。允许删除时提示影响、暂停受影响周期计划并标记缺失；保留历史任务。技能库删除仍是后续模块待办，未在本原型实现。
- `verify-workflow.cjs` 验证角色过滤、输入叠加、模型／确认／输入输出设置、四状态、启用门槛、删除及桌面／移动布局；不构成正式业务验收。

本节覆盖此前工作流列表及弹窗编辑的原型排版说明；原有任务与工作区设计规则不变。

### 角色、图标及工作区对话补充

工作流可配置适用角色（多选／通用）和图标，检查角色是否有权使用各技能；卡片明确显示默认确认方式及步骤可覆盖。工作区对话支持规则模拟的使用帮助、任务统计和任务意图反馈，周期请求在对话内形成可修改确认卡，不跳转任务新建页；创建仍需人工确认，错误邮箱需补齐。模型对话、邮件发送与自然语言通用理解尚未接通；邮件意图只记录在任务说明，不能宣称已配置可用的邮件执行链路。
