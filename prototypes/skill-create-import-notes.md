# 技能新建与导入 Demo：在原设计上补充

更新：2026-10-27。本文件与独立 Demo 不代表正式功能实现。

## 保留的设计

- 不改变现有技能库设计，不增加新的技能库首页、卡片布局或新建入口样式。
- 保留原四步：**基本信息、技能编写、资源文件、检查与发布**。
- 保留原编辑器的左侧步骤、中间表单、右侧文件树及预览、底部操作区。
- 保留已确认的图标／名称／标识同行、技能描述帮助、角色和默认／自定义模型选择。
- 导入保留原三步：**选择技能包、解析与预览、校验与导入**，导入为草稿后在同一套四步向导继续完善。

此前将新建步骤替换为“它是谁、要什么给什么、怎么做、补充资料”以及新增技能库首页的 Demo 已撤回，不作为后续 UI 实施依据。附件只作为功能补充依据，不替换已验收的布局与流程。

## 仅补充的内容

| 原步骤 | 补充 |
| --- | --- |
| 基本信息 | 名称／介绍的可点击示例和折叠反例、标识自动建议、描述字数与缺项提示，保留角色与模型区域 |
| 技能编写 | 保留工作指令、输入和输出；补示例／反例，提示工作指令应包含行动、完成标准和边界；分级、验收等仍写入同一指令区，不再拆成多个契约字段 |
| 资源文件 | 保留现有分类，补可跳过提示，脚本作为默认折叠的高级项，明确添加不代表执行 |
| 检查与发布 | 沿用原验证后明确发布的操作；补使用场景、步骤完成标准／边界检查，以及真实试用的推荐说明；没有实际运行不得称“已跑通” |
| 原导入三步 | 真正读取文件夹／ZIP，对照原内容和识别结果，缺失项提示在原向导补齐；保留扩展、未识别正文和资源，含脚本时确认来源但不执行 |

## 文件与数据边界

新建仅生成 **SKILL.md**，工作指令和输入输出写在同一份正文，不生成 contract.md。已有外部包的附带文件不擅自删除。系统标识按附件要求约束字符与长度，原平台元数据保留，不意味着工具执行能力完全兼容。

独立 Demo 不读取或修改正式技能库、配置和后端，不预置假发布卡片，不用浏览器持久化保存业务数据；保存、验证和发布只演示本页交互。正式导入仍需后端同标识冲突、引用保护及完整发布校验，此 Demo 不虚构用户真实引用关系。

提示只做初步结构检查，不按关键字替代业务判断。不同写法可由用户确认，正式执行与安全校验仍待后端实现。

## 输入来源的本轮补充

原“技能编写”中的输入卡片只声明资料名称、说明、文字／单文件／多文件、必填和可选数量要求；不增加实际附件、路径或前序步骤绑定控件。折叠说明解释Chat确认资料、任务文件／目录、前序输出、任务共享输入及授权Knowledge的来源分工。多文件最少份数可不填；提供资料时满足声明数量，可选资料允许不提供。

生成的SKILL.md记录输入定义和数量，不写入具体来源。导入兼容旧“文件／文件列表”和当前类型，数量可恢复。任务、Chat、工作流的正式绑定与运行调试按实施清单I01～I08逐模块落实。
